On the execution rates: fuzz_counter_reuse runs a keystream and compares
buffers, so it is fast; fuzz_explicit_curve and fuzz_key_pair each run
primality tests, scalar multiplications or lattice key generation per input,
which is why their counts are four orders of magnitude lower. A target that
does real public-key work measures depth per input, not inputs per second.

One defect, in a target rather than in the crate: fuzz_key_pair's first
session stopped on "Ed25519: a signature verified under a foreign key". Its
two 48-byte DRBG seeds differed only past byte 32, and Ed25519 takes the first
32, so both classes were one key pair. The guard now compares what each scheme
reads. Fixed in c804c50; the session above is after the fix.
