# Changelog

All notable changes to `cryptography-rs` are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
under Cargo's 0.x convention (a 0.x minor bump signals a breaking change;
0.x.y patch bumps are compatible).

## [Unreleased]

## [0.6.1] — 2026-05-08

### Added
- `pilot_hash` benchmark binary plus `scripts/bench_all_hash.sh` for hash-only
  sweeps; pilot binaries now honour the `PILOT_CONFIDENCE_LEVEL` environment
  variable.
- Scripts for three-platform Pilot merge, CSV extraction, and Kiviat radar
  generation (`scripts/merge_three_pilot_tables.py`,
  `scripts/build_radar_csvs.py`, `scripts/generate_three_platform_radar.py`).
- 2026-05-08 three-platform Pilot benchmark sweep across Wigner, Moore, and
  Darby, archived under `bench/sweep-2026-05-08/`.

### Changed
- Canonical performance tables refreshed against the 2026-05-08 sweep.

### Fixed
- Assorted small bugs surfaced by the post-sweep documentation audit.

## [0.6.0] — 2026-05-05

First publish under the post-NTRU-refactor architecture. Validated against all
400 NIST round-3 KAT vectors (HPS-509, HPS-677, HPS-821, HRSS-701).

### Added
- NTRUEncrypt **EES443EP1** — first product-form parameter set.
- NTRUEncrypt **EES541EP1** with pilot_pk targets.
- NTRUEncrypt **EES1087EP1** — 192-bit dense-trapdoor sibling of EES1087EP2.
- NTRUEncrypt **EES1499EP1**.
- Per-set byte-format regression digests for the IEEE 1363.1 EES sets
  (9 SHA-256 anchors).
- Full byte-for-byte validation against all 400 NIST round-3 KAT vectors
  (previously only `count = 0` was checked).
- NTRUEncrypt EES sizes table in `POSTQUANTUM.md`.

### Changed
- **Trait-based shared OWCPA + KEM core.** The per-set NTRU modules now
  implement `NtruVariant<const N, const LOGQ>`; the OWCPA and FO-KEM logic
  lives once in `ntru_pqc_shared` instead of being copy-pasted four times.
- Public API + tests are now generated by the `define_pqc_kem!` and
  `define_ees_set!` macros.
- `Trapdoor` dispatch consolidated into enum methods (`to_wire`, `from_wire`,
  `sample_iid`, `sample_via_igf`), replacing four scattered `match` sites.
- `NtruVariant::WEIGHT` no longer has a default — variants must set it
  explicitly, eliminating the silent-misuse footgun. (HRSS-701, which doesn't
  use fixed-weight sampling, sets `WEIGHT = 0` with a comment.)
- `kem_keypair_seeded` / `kem_enc_seeded` / `kem_dec` take stack scratch
  slices instead of allocating with `vec!`.
- MGF rejection sampler bounded with an assertion on the iteration counter.
- Module docstrings use KaTeX-rendered LaTeX for math instead of backtick
  ASCII.

### Security
- **Constant-time polynomial multiplication.** Removed the variable-time
  `if ai == 0 { continue; }` early-exit in `poly_mul_schoolbook` that leaked
  the zero pattern of the secret operands `f`, `r`, and `m`. Each `(i, j)`
  pair now issues exactly one `wrapping_mul` and one `wrapping_add`.
- **Side-channel boundary now enforced by the type system.** All thirteen
  per-set NTRU modules narrowed from `pub mod` to `pub(crate) mod`;
  external users reach the types only through `crate::vt::*`, the
  side-channel-aware namespace.

### Breaking
- The `pub mod` → `pub(crate) mod` narrowing above means any code that
  previously imported `cryptography::public_key::ntru_<set>::*` directly
  (rather than via `crate::vt`) will no longer compile. Migrate imports to
  the `cryptography::public_key::vt` namespace.
